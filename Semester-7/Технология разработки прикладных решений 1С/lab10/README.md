# Задание 10. Конфигурация «Контроль годности»

Базовая конфигурация — по лабораторной работе № 20 сборника 1С: учёт товаров
с контролем срока годности и списанием партиями.

| Объект | Комментарий |
|---|---|
| Справочник `Товары` | номенклатура |
| Документ `ПоступлениеТоваров` | ТЧ: товар, количество, срок годности партии |
| Документ `ПродажаТоваров` | ТЧ: товар, количество |
| Регистр `ОстаткиТоваров` | измерения «Товар» и «СрокГодности», ресурс «Количество» |
| Отчёт `ОстаткиТоваровТаблица` | исходный вариант — табличный документ |
| Отчёт `ОстаткиТоваровСКД` | вариант на схеме компоновки данных |

Количество хранится с тремя знаками после запятой — по условию нужен учёт до граммов.

Списание при продаже идёт по FEFO: пакетный запрос собирает потребность документа
и остатки партий, результат обходится по группировкам «товар → партии», партии
списываются по возрастанию срока годности. Если товара не хватает, проведение
отменяется с сообщением о недостающем количестве.

## 1) Убрано время после даты срока годности

Причина `00:00:00` в отчёте — тип «Дата» в 1С всегда хранит и дату, и время,
а по умолчанию выводится полное представление. Исправлено в двух местах:

- у измерения регистра и у реквизита табличной части состав даты выставлен
  в «Дата» (`<v8:DateFractions>Date</v8:DateFractions>`) — время просто не хранится;
- при выводе в табличный документ дата форматируется явно:
  `Формат(Выборка.СрокГодности, "ДЛФ=D")`.

Дополнительно при проведении поступления в регистр пишется `НачалоДня(СрокГодности)` —
страховка на случай, если дату ввели с временем.

## 2) Дополнительный отчёт на СКД

`ОстаткиТоваровСКД` строится на схеме компоновки: запрос к виртуальной таблице
остатков, ресурс «Количество» суммируется, сортировка по товару и сроку годности,
отбор по товару вынесен в пользовательские настройки.

Отличие от варианта на макете: настройки, отборы, группировки и итоги
пользователь меняет сам без изменения конфигурации, а компоновщик сам решает,
какие поля запрашивать у базы.
