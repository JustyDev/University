# Задание 2. Доработка конфигурации «Склад»

Базовая конфигурация «Простой склад» воспроизведена по учебному пособию
Семёнова (часть 1), плюс три доработки по заданию.

## Состав конфигурации

| Объект | Имя | Комментарий |
|---|---|---|
| Справочник | `ЦветаТоваров` | цвета товаров |
| Справочник | `СтраныТоваров` | страны-производители |
| Справочник | `Склады` | реквизит `АдресСклада` |
| Справочник | `Товары` | иерархический; `ЦветТовара`, `СтранаТовара` |
| Документ | `ПриходТоваров` | ТЧ `СписокТоваров`, движения «Приход» |
| Документ | `РасходТоваров` | ТЧ `СписокТоваров`, движения «Расход» + контроль остатков |
| Регистр накопления | `ОстаткиТоваров` | вид «Остатки»; измерения Товар, Склад; ресурс Количество |
| Отчёт | `ОстаткиТоваров` | на схеме компоновки данных |

## Что сделано по заданию

**1) Созданы подсистемы.** `Справочники`, `УчетТоваров` («Учёт товаров»),
`Отчеты` — все выводятся в командный интерфейс, объекты распределены по смыслу.

**2) В отчёте добавлены отборы по цвету и стране с необязательностью выбора.**
В варианте настроек «Основной» три отбора — `Склад`, `Товар.ЦветТовара`,
`Товар.СтранаТовара`. У каждого `use = false` и свой `userSettingID`, то есть
они выведены в пользовательские настройки и по умолчанию выключены: отчёт
формируется и без их заполнения.

**3) В расходный документ добавлено итоговое количество.** В управляемой форме
у табличной части включён подвал, колонка «Количество» связана с реквизитом
формы `ИтогоКоличество` через `FooterDataPath`. Значение пересчитывается в
`ПриСозданииНаСервере` и в обработчике `ПриИзменении` колонки количества.
Аналогичная форма сделана и для приходного документа.
